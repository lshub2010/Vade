# Beta 0.1.0 计划（草案）

状态：**进行中，未冻结**。目标版本 `0.1.0-beta`，统一 tag `v0.1.0-beta`；在功能冻结、独立审查和全量 CI 之前不打 tag、不建 Release。

## 1. 口径

Beta 覆盖需求文档中的绝大多数运行时能力，而不是只做一次版本号变更：

- 保留并发布现有 core、协议、会话/事件、审批、审计、模块路由与三端客户端。
- 补齐 memory（M4a）、自进化（M4b）、mcp-bridge（M5）。
- 补齐管理面记忆治理与多模型模块并存。
- 完成 Beta 发布工程：版本、README、部署文档、产物矩阵、校验和与已知缺口。

明确不作为 Beta 阻塞项：

- iOS 原生客户端（需求 §6 的移动端原生 UI 范围外；历史决定暂缓）。
- 生产代码签名、商店分发与自动更新通道（Beta 仍为 debug/unsigned，发布说明必须写明）。
- core 原生 TLS 之外的实验性平台、集群化/K8s、模块市场。

## 2. 当前基线

- 主仓 `dev_gingshan`：`rpc 1.8.0 / 50 methods`、`events 2.0.0 / 34`、34 错误码；全量 pytest 与三个契约/文档门禁可跑。
- 已有模块：echo、fs、shell、web、model；memory 与 mcp-bridge 尚未建仓。
- 已有客户端：Android、桌面、Web；真 core e2e、T2/T3/T6、模型发现已落地。
- 管理面：节点、拓扑、技能、审计、设置页面已有；记忆页面与后端路由仍未实现，当前返回 501。
- core 已有 `MemoryPort` 协议形状，但尚无实现；`engine._read_memory` 已预留注入点。

## 3. 波次与批次

### B0 · 契约与脚手架

- 冻结 Beta 范围与本计划。
- 建 `vade-module-memory`、`vade-module-mcp-bridge` 两个独立仓，按 echo 骨架起步。
- 确认 C-12 `memory.schema.json`、C-16 `memory-admin.json`、M5 manifest/上游配置边界。

出口：两个模块仓能独立启动、跑最小测试；主仓不需要改模块源码。

### B1 · M4a memory 存储与召回

- 两层记忆、去重、冲突、淘汰、session TTL、restart 召回一致。
- `remember` / `recall` / `forget` 工具；`memory/read_session` 与 `memory/admin_*` 私有 RPC。
- embedding 客户端可注入 fake；维度不一致拒绝启动；配额与 `MEMORY_FULL`。
- 单实例 `concurrency=exclusive`。

出口：模块仓测试全绿；独立启动自测；主仓 `MemoryPort` 适配器可接。

### B2 · M4b 自进化

- `turn_end`、`turn_review`、`session_close`、`consolidate`、`skill_evolve` 五个触发器。
- `pending/` 提案永不直接生效；关闭时零动作；所有 LLM 失败不阻塞会话。
- 幂等、预算、redact、审计、启动补跑。

出口：五个触发器各有测试；关闭/失败/重复运行有负例。

### B3 · mcp-bridge

- stdio/HTTP 上游、工具改名与冲突、未知 risk 按 high、动态 `capabilities.update`。
- 拆实例、上游断开保留旧工具表、图片不内联、2MB 结果上限。
- 凭据只从环境变量读，日志/ manifest 零泄露。

出口：假上游测试全绿；单上游实例故障隔离；能力更新原子。

### B4 · core memory 接线与管理面

- C-12/C-16 schema 与 ledger 登记。
- core 的 `MemoryPort` 适配器、`engine` 注入、admin memory 六路由替换 501。
- 管理面 `/memory` 页面：分页、详情链、晋升/归档/恢复/统计；浏览器只读、App 写。
- 写操作审计，读操作不审计；不返回原始对话、不提供编辑。

出口：管理面真 core 测试；浏览器 cookie 写请求 403；App Bearer 可写；记忆内容不进 SSE。

### B5 · 多模型模块与客户端缺口

- 解决同模块/跨模块 `chat` 冲突，支持多个 model 模块按 priority 选择。
- 客户端补齐仍未验证的连接状态、附件、ask_user、错误/取消体验。
- 管理面剩余占位页与导航一致性。

出口：两个 model 模块同时在线的选择测试；客户端三目标 CI 绿；真机/浏览器未验证项单列。

### B6 · Beta 发布工程

- 版本统一为 `0.1.0-beta`；客户端 `vadeVersion` 与 versionCode 同步。
- 重写 `README.md` 与 `README.zh-CN.md`：定位、Beta 能力、下载/安装、模块表、已知缺口、文档索引。
- 更新 `docs/DEPLOYMENT*.md`、release notes、ALPHA/LEDGER/status 一致性。
- 产物：core 双架构 tar、5+2 模块 wheel/sdist/manifest、客户端 APK/MSI/zip/Web、`SHA256SUMS`。
- 干净环境安装冒烟、包内 `import vade, vade_protocol`、校验和核对。
- 独立只读发布审查；P0 关闭后才打 tag。

## 5. 门禁

- 每批：独立只读审查；父代理复跑；CI 绿；只提交本批文件。
- 模块仓：自带测试与 CI；主仓不复制模块源码。
- 不把“代码存在”写成“已验收”；skip 必须记录原因与本地复跑命令。
- Beta 发布前至少一轮全量回归：core pytest、契约三件套、客户端三目标、模块测试、干净安装。
- 功能冻结后只接受 P0/P1 修复；README 与 release notes 以冻结提交为准。

## 6. 已知风险

- memory 的 embedding 依赖外部 OpenAI 兼容端点；测试必须用可注入 fake，不能把网络当默认。
- M4b 的 LLM 触发器有预算与失败路径，容易在“关闭时零动作”上假绿。
- mcp-bridge 的上游风险未知时默认 high，审批路径必须真实覆盖。
- 多模型模块并存会触碰 registry 的工具冲突规则；先改规则测试再改实现。
- 管理面记忆页与 core 路由必须走私有 RPC，禁止直连 SQLite。
