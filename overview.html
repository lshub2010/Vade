一、这个系统是什么

内核薄、能力外挂。 core 只做四件事：连接与注册、调用路由、Agent 循环、密钥与审计。其余一切——工具、记忆、模型、以及桌面/手机/浏览器客户端——都是独立进程，可跨机器，主动连上来注册。客户端不是 core 的一部分，它是一个 ui 模块，和你写的 fs 模块在协议上是同一种东西。

admin-ui 独立 :8444（默认回环，可对外，浏览器只读）· 模块 app 自托管 :8080

三个面不同源：数据面 :8443、管理面 :8444（默认回环，可显式对外）、模块 app 由 ui 模块自己 serve。同源会让模块的一个 XSS 直接读走管理 API——HttpOnly 只防读 cookie，不防借用 cookie 发请求。

一条不可破的判据：core 源码里搜不到任何具体模块的 id / 名称 / 路径；删掉所有模块，core 仍能启动。这条会写成会失败的测试，不是口号。

三、求求骨架

域 要求 关键约束
FR-1 内核 只保留循环、路由、注册、密钥、审计 不 import 任何模块代码
FR-2 协议 manifest 自描述 + JSON-RPC 未知字段必须忽略（前向兼容）
FR-3 传输 WSS 必须 版本不匹配拒连，禁止协商降级
FR-4 信任 白名单 + 配对 + 逐模块吊销 任何持公钥者不能注册
FR-5 模块形态 独立进程 / 依赖 / 测试 / 失败 / 观测，且模块间零横向依赖 五条缺一即"拆开的代码"
FR-6 能力类型 tools / prompts / events / memory / model 多实例三态并发
FR-7 审批 risk=high 必须确认 超时 fail-closed，显示完整参数
FR-8 UI 全模块化，多端同步 皮肤 × 底栏正交，9 组合可用
FR-9 配置页 唯一内置 UI 只管模块，不管业务
FR-10 审计 追加写、不可改 SQLite，按天分表，留 30 天

非功能指标：模块接入 < 5s · 工具调用 P95 < 2s（本机）· 单模块故障不影响会话 · 抓包 0 明文 · 冷启动 < 3s。

ChaCha20-Poly1305；nonce 由 Noise 传输态维护，方向隔离靠 Split 出的两把独立密钥——反射帧用另一把密钥解密必然失败。帧头 counter 只用于重放检测，不参与 AEAD。

握手

场景 参数集 轮次
已配对模块重连 Noise_IK_25519_ChaChaPoly_BLAKE2s 1-RTT
首次配对 Noise_XX_..._BLAKE2s + 配对码 PSK（8 位中英混合，180s，一次性） 2-RTT

用 snow 库，不自研密码学状态机（这是 v1.0 → v1.1 最大的一处推翻）。

鉴权三模式

模式 场景 端到端加密
module_key 服务端模块 是 · Noise
device_key 桌面/移动原生端 是 · Noise
browser_session 浏览器 否 · 止于 TLS（不存私钥，不给假安全）

另有两段不在 E2E 范围内：bridge ↔ 上游 MCP（bridge 进程内明文）、core 进程内部（同进程内存）。E2E 只保护传输中的消息，不覆盖静态存储——core.key 与 SQLite 都是明文落盘，靠全盘加密。

会话与队列

  • seq per-session 单调递增，core 分配
  • replay buffer 1000 条 / 24h，attach(last_seq) 增量补发，不覆盖则给快照
  • 每会话同时只有 1 个 running turn，其余 FIFO 排队
  • 中断 → 发 tools/cancel → 立即释放队列，不等模块

记忆与自进化（D40–D46）

记忆不是一张表，是两层，因为「刚才说过什么」和「用户三年前说过什么」不能抢同一张召回表：

session global
读法 按预算注入当前对话（字符硬顶 4200），不检索 按求 recall（单次 ≤800 token）
来源 evolver 每轮抽 + 每 10 轮复盘 跨会话出现 ≥2 次；lesson 1 次带证据；或用户显式说"记住"
生死 会话关闭 + 7 天 永久，受 5000 条配额

自进化五个触发器，全是确定性的，不靠 system prompt 提醒模型「要不要记点什么」——那种做法不可测、不可关、还白占主对话 token：

触发 干什么 调 LLM
turn_end（每轮） 规则抽取 0–2 条候选进 session，只从 user 文本抽 否
turn_review（每 10 轮） 旁路复盘骨架 → ≤3 条 + ≤1 lesson 进 staging 1 次 / 10 轮
session_close（≥6 轮） 读 rolling summary + 最后 10 轮 → 总结 + 候选 1 次
consolidate（每日 + 启动补跑） 聚类、冲突、晋升、衰减、淘汰 批量 1 次
skill_evolve 成功且未自纠的轨迹提炼 skill 1 次

为什么加 turn_review：只靠会话末总结，等于等人死了才写遗书——长会话中途的决策会丢，且一次吞全文很贵。每 10 轮复盘一次，输入是结构化骨架（≤1.5k token），成本降一个量级；纯自主运行（用户全程不说话）时，也只有这条通道能学到东西。

教训（lesson）单列：kind ∈ {fact, preference, lesson}。lesson 用四段式 when / do / pitfall / verify，带 evidence，单次即可进 agent:lessons 但标 unverified（confidence ≤0.6），二次验证才升 0.8。失败轨迹只产 lesson、不产 skill——否则会把"先错后补"学成最佳实践。

熵增有五种形态，各有对策，不是一句"定期清理"能盖住的：

形态 对策
重复 哈希去重 + 语义聚类合并（只合并不删原文）
矛盾 supersedes 软失效，不覆盖；判不准两条都留
过时 时间衰减进 score（30 天半衰）+ 显式 forget
膨胀 skill 上限 64；create 前必须检索，命中相似只能 patch
腐化 加载校验 requires_tools；连续 3 次失败转 stale 退出注入

skill 是 core 的文件，模块碰不到。所以演化只能提提案：pending/ 不参与注入、要人审、带 revision 可回滚。pending/ 一旦能注入，D38「skill 不含执行通道」就形同虚设。

上游 MCP 不算节点（D39）：知识库这类外置能力挂在 mcp-bridge 上游，不握手、不注册、不能被别的模块路由——判定「是不是模块」的三条硬标准见方案 §2.7.1。想让它故障隔离，就一个上游拆一个 bridge 实例，拓扑上自然变成多个节点。

一个模块一个节点（D35）：工具不进画布。fs 的 4 个工具、mcp-bridge 的几十个工具，都只在节点侧栏里列成一张可折叠的表。画布回答「谁连上来了、健不健康」；工具清单回答「它能干什么」——混在一张图上，两边都读不清。

三个扩展点，别混用（D38）：

层 能执行 进拓扑 进审计 什么时候用
module 是，走协议 是 工具级 求要新能力、求要审批
prompt 片段 否 否 否 单个模块的用法说明
skill 否，只能用已有工具 否 只记名字 跨模块的编排知识

skill 不能自带执行通道，三条理由：不可审计、权限借道、不可治理。要跑脚本就做模块，要写说明书就写 skill，中间没有第三种东西。

「编辑」分三层，第四层明确不做：

层 能做什么 生效
L1 布局 拖位置、改别名、分组、折叠 立即（仅布局，存 core，多端一致）
L2 治理 启用/停用、吊销、断开重连、覆盖并发模型、生成配对码 立即影响运行态 + 审计
L2.5 邀请位 放一个占位节点 → 出二维码 → 模块接入后原地转实心 等待态
L3 编排 在画布上新建模块并让 core 拉起进程 不做

L3 不做，是因为 core 一旦承担「拉起模块」，就得拿到那台机器的启动方式和凭据，从「消息中枢」变成「集群调度器」——这和「私钥只在 core」的安全模型正好相反，还把故障域从「一个模块挂了」扩大到「编排器挂了全挂」。跨机部署继续交给 compose / k8s，画布只负责把已经连上来的东西管好。
