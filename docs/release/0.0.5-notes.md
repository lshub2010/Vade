# Vade 0.0.5-alpha

Fifth alpha of Vade (偕行). Pre-release: protocol/UI may still change. Back up before upgrading.

## Highlights

### Discovery retry is honest (0.0.5)

- Settings → Default model's discovery failure now offers a real **retry upstream refresh** action; it sends `model/discover`, not merely another `model/list`.
- A normal list failure still retries `model/list`; the two failure sources are kept separate.
- If core answers from its 2 s failure cooldown (`cached=true`), the client keeps the failure visible and says it reused the cache instead of pretending the retry succeeded.
- A missing/terminal discovery capability (old core, module/mock, read-only) still hides the control; the verdict is remembered on the connection so it does not reappear on every page.
- The first catalog pull is marked in-flight synchronously, closing the first-frame window where a click could start a second discovery.

### Core hardening

- Discovery cache writes use a unique `mkstemp` temp file, `fsync` the file and directory, then atomically replace; a failed discovery never overwrites the last good file.
- A production-assembly test now boots the real `App.startup()` + `install_components()` path and verifies the resolver's cache path.
- No protocol or schema change in this release; C-05 stays 1.8.0 / 50 methods.

## Known gaps

- The settings retry path has state-level tests but no UI render test proving the button text/click sends exactly one frame; treat that as an evidence gap, not a completed UI test.
- Discovered rows and configured rows still both use `provider=builtin` on the wire; there is no source badge yet.
- The persisted list is a derived cache: startup does not re-probe the upstream, and an upstream `200` with an empty `data` still replaces the list with an empty one.
- Multi-model-module coexistence, real-model tool-call end-to-end (T3), Web real-browser pairing, iOS, memory/M4b, mcp-bridge and production signing remain out of this release.
- APK debug-signed, desktop unsigned; no update channel.
