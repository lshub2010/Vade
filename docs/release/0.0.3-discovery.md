# 0.0.3 · 上游 `/v1/models` 自动发现（设计记录）

状态：已实现（core 83c227a，client 待发布）
目标：管理员只填 `base_url` + key，客户端点“刷新列表”即可看到上游真实模型，而不是只能手写 `[llm].model`。

## 已落地

- `core/vade/llm/openai_compat.py`：`OpenAICompatProvider.list_models()`
  - `GET {base_url}/models`，只取 `data[].id`，去重、去空、保持服务端顺序；
  - key 只从 `api_key_env` 指定的环境变量读；没有 key 时不发 `Authorization`；
  - 非 2xx 抛错，**不返回空列表**（空列表会被误读成“上游没有模型”）。
- `core/tests/llm/test_openai_compat_models.py`：3 条（顺序/去重/坏行、无 key、503 不吞）。

## `model/discover` RPC（已实现）

```json
{
  "method": "model/discover",
  "params": {},
  "result": {
    "revision": 12,
    "models": [ ... model/list entry ... ],
    "discovered_at": "2026-11-23T16:20:00Z",
    "cached": false
  },
  "errors": ["UNAVAILABLE", "INTERNAL"]
}
```

- 只允许 `llm.provider in {builtin, openai, openai_compatible}` 且 `llm.base_url` 非空；
  其他模式返回 `UNAVAILABLE`（模型模块自己声明列表，core 不替它探测）。
- 缓存进程内，成功才替换；失败保留上一次好列表，返回 `UNAVAILABLE` + 原因摘要。
- 冷却 2s，避免刷新按钮把 core 变成对上游的放大器。
- 发现条目的 `id = builtin/<upstream-id>`，`display_name = upstream-id`；
  能力字段保持 `null`（不按模型名猜上下文/视觉/工具能力）。
- 发现后 `catalog.revision` 递增，客户端用 `model/list?if_revision` 正常拿增量。
- `session/model.set` 已按 catalog 校验，发现条目天然可选；turn 的
  `builtin/<id>` 前缀由 `OpenAICompatProvider.chat` 剥离后发上游。
