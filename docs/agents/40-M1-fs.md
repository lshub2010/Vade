## 一、一句话任务

给模型读写文件的能力，同时保证它**只能**碰配置里允许的那几个目录——`../../etc/passwd` 和指向外面的软链都必须失败。

## 四、工具规格

| 工具 | 参数 | risk | timeout |
|---|---|---|---|
| `read_file` | `path: str, max_bytes: int = 262144` | low | 10s |
| `write_file` | `path: str, content: str, if_exists: str = "error"` | **high** | 15s |
| `list_dir` | `path: str, depth: int = 1` | low | 10s |
| `search_files` | `pattern: str, root: str = "", limit: int = 50` | low | 30s |

配置（`FS_ROOTS`，冒号分隔；默认空 → 所有调用拒绝）：

```toml
[fs]
roots = ["/data/workspace", "/tmp/agent"]
deny  = [".ssh", ".git", ".env", "id_rsa"]
max_read_bytes = 262144
max_write_bytes = 1048576
max_entries = 2000
```

## 五、安全实现（这一节是重点）

### 路径校验（每个工具、每次调用都走同一个函数）

```python
def resolve_under_roots(path: str, roots: list[Path]) -> Path:
    p = Path(path)
    if not p.is_absolute():
        p = roots[0] / p
    real = p.resolve(strict=False)          # 解析 .. 与软链
    for root in roots:
        r = root.resolve()
        if real == r or r in real.parents:  # 必须真在根内
            for d in deny:
                if d in real.parts:
                    raise ToolError("PERMISSION_DENIED", f"path is denied: {d}")
            return real
    raise ToolError("PERMISSION_DENIED", "path escapes configured roots")
```

**必须写对的三个细节**：
1. 先 `resolve` 再判断，不能先判断再 resolve（软链在判断后才解析就晚了）。
2. 根目录本身也要 `resolve`（根可能自己是个软链）。
3. 判断用 `Path.parents`，不要用字符串 `startswith`（`/data/workspace-evil` 会骗过前缀判断）。

### 各工具

- `read_file`：必须 UTF-8；解码失败 → `INVALID_ARGUMENT("not a text file")`。超过 `max_bytes` 截断并在结果里 `truncated: true`，**不报错**。
- `write_file`：默认 `if_exists="error"`（防覆盖）；`"overwrite"` 才覆盖。原子写：同目录临时文件 + `os.replace`。父目录必须存在，不自动创建。内容超限 → `PAYLOAD_TOO_LARGE`。
- `list_dir`：`depth ∈ [1,3]`；条目数超 `max_entries` 截断并标记；不跟随软链目录（`follow_symlinks=False`）。
- `search_files`：pattern 用 `fnmatch`，**不要**把用户输入拼进 `glob` 递归（`**` 会炸）；用 `os.walk` + 深度上限 + 命中数上限；跳过 deny。

### 输出

```json
{"ok": true, "result": {"path": "...", "content": "...", "truncated": false, "bytes": 123}}
```

结果里**不回显绝对根路径之外的任何信息**（错误信息里也不带宿主目录结构）。

## 六、验收（五道门）

```bash
cd modules/fs

# 门 1 独立运行
python -m fs_module --standalone read_file --args '{"path":"/data/workspace/a.txt"}'

# 门 2 独立测试（不装 SDK）
pip install pytest && pytest tests/test_tools.py -q

# 门 3 独立部署
docker build -t vade/fs:dev . && docker run --rm -v /tmp/agent:/data/workspace vade/fs:dev \
  --standalone read_file --args '{"path":"/data/workspace/a.txt"}'

# 门 4 独立失败（连上 core 后）
kill -9 $(pgrep -f fs_module)   # core 与其他模块不受影响

# 门 5 独立观测
python -m fs_module --standalone list_dir --args '{"path":"/data/workspace"}' 2>&1 | head
# 日志每行含 module_id / instance_id / tool / duration_ms

# 安全（必须全部非零退出 + 可读错误）
python -m fs_module --standalone read_file --args '{"path":"../../etc/passwd"}'
python -m fs_module --standalone read_file --args '{"path":"/data/workspace/link-to-etc"}'
python -m fs_module --standalone read_file --args '{"path":"/data/workspace/.ssh/id_rsa"}'
```

`tests/test_security.py` 至少覆盖：`..` 逃逸、绝对路径越界、软链逃逸、软链目录、根目录为软链、`/data/workspace-evil` 前缀欺骗、deny 命中、超大文件截断、非 UTF-8、写入覆盖保护。

## 七、禁止

- 禁止 `os.path.abspath` 代替 `resolve`（不解析软链）。
- 禁止用字符串前缀判断路径归属。
- 禁止自动创建父目录（会让模型到处建目录）。
- 禁止在 `tools.py` import SDK。
- 禁止把 `roots` 配成 `/`（README 里要写这条警告）。
- 禁止返回宿主机的目录树/用户名。
