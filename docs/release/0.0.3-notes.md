# Vade 0.0.3-alpha

Third alpha of Vade (偕行). Pre-release: protocol/UI may still change. Back up before upgrading.

## Highlights

### Model discovery (0.0.3)

- New `model/discover` RPC (C-05 1.8.0) asks the builtin OpenAI-compatible upstream for `GET {base_url}/models` and appends each id to `model/list` as `builtin/<id>`.
- The client model sheet has a **refresh** button; a successful discovery re-reads the catalog and the new ids become selectable like any other model.
- The cache is process-local and replaced only on success: a 401/503 keeps the last good list. A 2 s cooldown prevents a refresh button from becoming a request amplifier.
- Capability fields stay `null` for discovered models — nothing is inferred from a model name.

### Core

- `model/discover` handler with `not_discoverable` (module/mock/empty base_url) and `upstream_error` (failure keeps the last list) branches.
- Contract C-05 1.7.0 → 1.8.0, append block 13, ledger 50 methods; contract/ledger/docs gates updated.
- Existing 0.0.2 fixes remain: snapshot bounds/clipping, approval args preservation, config/admin hardening, UI session persistence, per-session event routing.

### Client

- Upstream model refresh in the model sheet; failure stays visible and never blanks the list.
- Android application id `io.github.lshub2010.vade`; debug-signed APK.
- T1 connection badge / mid-chat notice, T5 wasm first pairing, ask-user cards, pairing persistence, full history on re-entry, navigation/chat/effect/blur fixes.

## Known gaps

- Real-model tool-call end-to-end (T3) is deferred; built-in/mock paths are covered.
- A discovered model selected in a session is valid only while the discovery cache lives in the core process; after a core restart the cache is empty and that session's next turn fails with `UNAVAILABLE` until the user refreshes or picks another model. A startup discovery/hydration is not implemented.
- Multi-model-module coexistence still needs a separate RFC (`chat` tool conflict).
- Web first pairing requires a same-origin page or allowlisted Origin; real browser run is not verified in CI.
- iOS, memory/M4b and mcp-bridge are not in this release.
- APK debug-signed, desktop unsigned; no update channel.
- Module pairing codes remain unavailable; manual whitelist is documented in the deployment guide.
