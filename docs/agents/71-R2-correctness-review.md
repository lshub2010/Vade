# R2 · 审查 B：产物正确性

> 第二轮独立审查。R1 看「做没做对的事」，你看「做出来的东西在边界上会不会坏」。
> 不要重复 R1 的规格检查；只查实现质量与测试有效性。

## 一、输入

同 R1 的 1–6 项。额外要求：**能跑起来的环境**（依赖已装、测试可执行）。跑不起来的，判 `reject`「不可验证」。

## 二、逐项检查

### 1. 边界条件
逐个问：
- 空值 / `null` / 空字符串 / 空列表
- 0 / 负数 / 极大值 / 浮点精度
- 超长（字符串、路径、URL、命令、消息体）
- 超限（工具数、并发、payload、token）
- Unicode（emoji、RTL、零宽字符、非法 UTF-8）
- 时区 / 时钟回拨（seq、超时、审计时间）

对每个边界，找到对应的测试；没有测试的记为 `advisory`，行为明显错的记为 `blocking`。

### 2. 异常路径
- 下游超时、连接拒绝、DNS 失败、TLS 失败
- 部分成功（3 个工具调 2 个成功）
- 重试是否幂等？会不会重复执行高危操作？
- 错误是否结构化（`{code,message,retriable}`）？有没有 traceback 泄漏到用户侧？
- 中断（`CancelledError`）是否被正确传播？有没有被 `except Exception` 吞掉？

### 3. 并发与状态
- 共享可变状态是否有锁/单 writer？逐处检查：
  - C2：每连接写队列
  - C3：队列、seq、approval 状态机
  - C5a：审批竞争、审计批量写
  - M4：内存向量矩阵与 SQLite 同步
- 是否有「先检查后使用」的竞态（TOCTOU）？特别看 `fs` 的路径校验与写入。
- 重复事件、乱序事件、重连重叠：会不会导致状态错乱？
- 进程重启后：未完成状态是否被正确清理/恢复？

### 4. 兼容性
- 旧数据（SQLite schema 变更）能否读？
- 旧配置（缺字段）能否启动？
- 旧客户端（少字段）能否工作？未知字段是否被忽略？
- 协议次版本/补丁版本的处理是否符合 FR-2.2？

### 5. 测试有效性（重点，最容易假绿）
- 断言是否真的能发现问题？例如 `assert result is not None` 等于没测。
- 是否只测 happy path？统计负向用例占比，< 30% 记 `advisory`。
- 有没有 `pytest.skip` / `@Ignore` / `try: ... except: pass` 掩盖失败？
- 有没有测试之间共享状态导致顺序依赖？（打乱顺序跑一次）
- 对关键安全用例，做一次**变异验证**：临时改坏实现（本地不提交），确认测试变红，然后还原。至少做 2 个：
  - 去掉 `fs` 的 `resolve()` → 逃逸测试应变红
  - 去掉 `web` 的 IP 校验 → SSRF 测试应变红
  - 去掉 counter 单调校验 → 重放测试应变红
- 覆盖率不是判据；**分支覆盖**与负向用例才是。

### 6. 资源与性能
- 内存：大 payload 是否预分配？流式读取有没有上限？
- 句柄：连接、文件、子进程是否都释放？（`lsof` / `ps` 前后对比）
- 背压：慢消费者会不会把内存吃满？
- 是否有明显的 O(n²)（例如每次 recall 重算全量 embedding）？
- NFR 指标是否实测（不是估算）：握手 < 50ms、1KB 加解密 < 2ms、重连 < 5s。

### 7. UI 专项（U 批）
- 9 组合是否真的在同一构建内切换？有没有偷偷重启？
- 断网/弱网下是否白屏？空态是否有文案？
- 动态字体 / 深色 / 窄屏是否塌陷？
- 截图是否与当前 commit 对应（看时间戳与 UI 文案）？

## 三、判定

`reject` 的硬条件（任一）：
- 关键路径有未处理异常会导致进程崩溃
- 并发竞态可复现
- 安全用例是假绿（变异后仍通过）
- NFR 指标未实测或明显不达标且无说明
- 资源泄漏（句柄/内存）可复现

## 四、输出格式

```json
{
  "batch": "<BATCH>",
  "reviewer": "R2",
  "verdict": "pass|reject",
  "blocking": [{"file": "...", "line": 0, "issue": "...", "repro": "命令或步骤", "fix": "..."}],
  "advisory": [{"file": "...", "line": 0, "issue": "...", "fix": "..."}],
  "mutation_checks": [
    {"target": "fs.resolve", "test": "test_security.py::test_symlink_escape", "turned_red": true}
  ],
  "nfr_measured": {"handshake_ms_p95": 0, "aead_1kb_ms_p95": 0, "reconnect_s": 0}
}
```

## 五、禁止

- 禁止只读 diff 不跑测试。
- 禁止把「有测试」当作「测试有效」。
- 禁止提出风格类意见（命名、空行）占用阻断项名额。
- 禁止修改代码。
