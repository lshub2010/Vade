# Vade 0.0.4-alpha

Fourth alpha of Vade (偕行). Pre-release: protocol/UI may still change. Back up before upgrading.

## Highlights

### Discovered models survive a core restart (0.0.4)

- The last successful `model/discover` list is written atomically to `models_discovered.json` in `core.data_dir` (mode `0600`) and hydrated at startup.
- A session that selected `builtin/<upstream-id>` no longer fails with `UNAVAILABLE` after a core restart; the id stays selectable until the next refresh.
- The cache contains only upstream model ids and `discovered_at` — no API key, base URL, or inferred capabilities.
- A failed refresh still keeps the last good in-memory list and never overwrites the persisted file. A corrupt/unreadable cache is ignored at startup instead of preventing boot.
- The configured `builtin/<llm.model>` keeps priority 0; discovered rows stay at priority -1, so hydration cannot silently change the default model.
- Settings → Default model now has a **refresh upstream models** entry in addition to the chat model sheet's refresh button. It is hidden for fixtures and read-only cores; after an old core or a module/mock provider answers `not_discoverable`/`unknown method`, the adapter remembers the verdict and later pages hide it too.

## Known gaps

- The persisted list is a cache, not a capability database: ids are restored as-is and are not re-probed at startup. If the upstream removed a model, it remains listed until a successful refresh.
- A discovered row and a configured row still both use `provider=builtin` on the wire; there is no source badge yet.
- Multi-model-module coexistence still needs a separate RFC (`chat` tool conflict).
- Real-model tool-call end-to-end (T3) is deferred.
- Web first pairing requires a same-origin page or allowlisted Origin; a real browser run is not verified in CI.
- iOS, memory/M4b and mcp-bridge are not in this release.
- APK debug-signed, desktop unsigned; no update channel.
